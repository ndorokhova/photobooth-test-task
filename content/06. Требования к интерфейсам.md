# Требования к пользовательским интерфейсам

Требования относятся к сценарию [[03. Use cases#uc-01|UC-01. Отправка фотографии на электронную почту]].

## Экран 1. Выбор фотографии {#screen-1}

### Макеты состояний

#### 1.1. Отправка доступна

![[interfaces/photo_01.jpg|360]]

| 1.2. Нет интернет-соединения | 1.3. Заявка уже принята |
|:---:|:---:|
| ![[interfaces/photo_02.jpg\|240]] | ![[interfaces/photo_03.jpg\|240]] |
### Состав и представление

| ID | Требование |
|---|---|
| UI-01 | Экран должен отображать фотографии, созданные в текущей пользовательской сессии, и визуально выделять выбранную фотографию. |
| UI-02 | Экран должен отображать доступные способы получения фотографии, включая действие «Отправить на электронную почту». |
### Состояния элементов

| ID | Требование |
|---|---|
| UI-03 | Если фотография выбрана и интернет-соединение доступно, действие «Отправить на электронную почту» должно быть активно. |
| UI-04 | При отсутствии интернет-соединения действие должно быть неактивно, а на экране должна отображаться причина «Нет подключения к интернету». |
| UI-05 | После принятия заявки действие должно быть недоступно до завершения сессии. Остальные способы получения фотографии должны оставаться доступными. |
### Поведение

| ID | Требование |
|---|---|
| UI-06 | Пользователь должен иметь возможность выбрать одну фотографию. После выбора клиентское приложение фотокиоска должно проверить наличие интернет-соединения. |
| UI-07 | Выбор действия «Отправить на электронную почту» должен открывать экран 2 «Отправка фотографии». |

### Состав и представление

| ID | Требование |
|---|---|
| UI-08 | Экран должен отображать превью выбранной фотографии, поле ввода электронной почты и экранную клавиатуру. |
| UI-09 | Экран должен содержать элемент подтверждения согласия и ссылку на документ об обработке персональных данных. |
| UI-10 | Экран должен содержать действия «Отправить» и «Назад». |
### Состояния элементов

| ID    | Требование                                                                                                                                                               |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| UI-11 | Действие «Отправить» должно быть доступно, если адрес электронной почты заполнен в установленном формате и согласие на обработку персональных данных предоставлено. В остальных случаях действие должно быть неактивно. |
| UI-12 | Если введённый адрес не соответствует установленному формату, поле должно быть визуально выделено и должно отображаться сообщение «Проверьте адрес электронной почты». |
### Поведение

| ID | Требование |
|---|---|
| UI-13 | Клиентское приложение фотокиоска должно проверять формат введённого адреса и обновлять состояние поля и действия «Отправить». |
| UI-14 | Пользователь должен иметь возможность исправить адрес без повторного выбора фотографии. |
| UI-15 | Выбор ссылки на документ об обработке персональных данных должен открывать экран 3. После возврата на экран 2 введённый адрес электронной почты должен сохраняться. |
| UI-16 | Выбор действия «Назад» должен открывать экран 1 и очищать введённый адрес. |
| UI-17 | Выбор доступного действия «Отправить» должен открывать экран 4 «Ожидание результата». |

## Экран 4. Ожидание результата {#screen-4}

![[interfaces/photo_07.jpg|360]]

### Состав и представление

| ID | Требование |
|---|---|
| UI-21 | Экран должен отображать выбранную фотографию, адрес получателя и индикатор обработки запроса. |
| UI-22 | Экран должен информировать пользователя о необходимости дождаться результата. |
### Состояния элементов

| ID | Требование |
|---|---|
| UI-23 | Во время ожидания результата повторная отправка и переход к другим действиям должны быть недоступны. |
### Поведение

| ID | Требование |
|---|---|
| UI-24 | Клиентское приложение фотокиоска должно ожидать ответ Backend API не более 15 секунд. |
| UI-25 | При принятии заявки должен открываться экран 5 в состоянии 5.1. При получении ошибки от Backend API или отсутствии ответа в течение 15 секунд должен открываться экран 5 в состоянии 5.2. Техническая причина ошибки пользователю не отображается. |

### Состав и представление

| ID | Требование |
|---|---|
| UI-26 | Экран должен отображать выбранную фотографию, адрес получателя, результат обработки и доступные дальнейшие действия. |
### Состояния элементов

| ID | Требование |
|---|---|
| UI-27 | В состоянии 5.1 должно отображаться сообщение «Фотография принята к отправке» и пояснение, что письмо будет отправлено на указанный адрес. |
| UI-28 | В состоянии 5.1 должны отображаться действия «Завершить работу» и «Выбрать другой способ». |
| UI-29 | В состоянии 5.2 должно отображаться сообщение о том, что фотографию не удалось отправить, и предложение повторить попытку. |
| UI-30 | В состоянии 5.2 должны отображаться действия «Повторить отправку» и «Вернуться к выбору фотографии». |
### Поведение

| ID | Требование |
|---|---|
| UI-31 | Выбор действия «Завершить работу» должен завершать пользовательскую сессию и открывать стартовый экран. |
| UI-32 | Выбор действия «Выбрать другой способ» должен открывать экран 1. Пользовательская сессия должна оставаться активной. |
| UI-33 | Выбор действия «Повторить отправку» должен повторно открывать экран 4. |
| UI-34 | Выбор действия «Вернуться к выбору фотографии» должен открывать экран 1. Выбранная фотография должна оставаться доступной для выбора другого способа получения. |
